# НМОУ Вектор

Контекст платформы мониторинга бизнеса, в котором права, рабочие данные и история действий принадлежат серверу.

## Аккаунты и область данных

**Организация**:
Единственная компания, рабочие данные которой принадлежат конкретному экземпляру сайта. Организация не создаётся, не выбирается и не отключается внутри приложения; для другой компании разворачивается отдельный экземпляр сайта.
_Avoid_: Бизнес-аккаунт, tenant, выбор бизнеса

**Область аккаунта**:
Серверная граница доступных данных: платформа для администратора или организация для любого неадминистративного аккаунта. Идентификатор бизнеса и подразделения в текущей модели отсутствуют.
_Avoid_: Business scope, businessAccountId, подразделение, department scope

**Единое рабочее пространство**:
Общий интерфейс всех неадминистративных аккаунтов. Доступные пользователю вкладки определяются его должностью; отдельные кабинеты руководителя, работника и диспетчера отсутствуют.
_Avoid_: Базовый кабинет, кабинет роли, отдельный интерфейс должности

**Должность**:
Серверная настройка названия и набора рабочих вкладок, которую наследуют назначенные ей аккаунты. Любая неадминистративная должность может сочетать любые рабочие вкладки, но не административные разделы.
_Avoid_: Тип кабинета, индивидуальные галочки аккаунта, административная вкладка сотрудника

**Редактируемый раздел БД**:
Административное представление только пользовательских полей, которые видны в рабочих кабинетах и реально влияют на поведение системы. Технические и исторические данные продолжают храниться, но не показываются и не редактируются через этот экран.
_Avoid_: Сырая таблица, системный ID, raw payload

## Лабораторный контроль

**Раздел лабораторного контроля**:
Один из двух контуров результатов испытаний: входящий контроль сырья либо контроль готовой продукции.
_Avoid_: Отдельная форма как отдельная вкладка, тип аккаунта лаборатории

**Матрица лабораторных испытаний**:
Server-owned каталог поддерживаемых показателей с их ГОСТ, профилей сырья и видов готовой продукции из вкладки Google Sheets `Лаборатория`. Все показатели всегда открыты для ввода, а отметки профиля определяют условные строки печатного протокола.
_Avoid_: Захардкоженный список полей frontend-а, свободный набор показателей

**Результат испытаний**:
Неизменяемая серверная запись одной даты анализа и одного объекта испытаний с обязательными целью и примечанием к протоколу; во входящем контроле она объединяет одну или несколько проб, а в контроле готовой продукции содержит хотя бы один поддерживаемый показатель. Лаборант определяется активной сессией.
_Avoid_: Клиентский автор, локальная запись браузера, результат без показателей

**Проба входящего контроля**:
Часть одного результата входящего контроля со своим номером пробы или идентификатором транспорта и хотя бы одним поддерживаемым показателем. Все пробы отчёта используют общие дату, свободно введённый объект испытаний и контекст документа/транспорта.
_Avoid_: Отдельный отчёт на каждый номер пробы, проба без идентификатора или показателей

**Протокол испытаний**:
Формируемое backend-ом PDF-представление неизменяемого результата испытаний. Постоянная шапка принадлежит серверному шаблону, условные строки показателей и ГОСТы берутся из снимка матрицы на момент сохранения результата, а значения, пробы и лаборант — из самого результата; старые записи без снимка используют актуальную матрицу как совместимый fallback.
_Avoid_: PDF из клиентского DOM, редактируемый протокол, повторное чтение изменившейся матрицы для нового результата

**Вид готовой продукции**:
Строка раздела `Готовая продукция` из матрицы лабораторных испытаний; конкретная марка выбирается отдельно из общей номенклатуры, а набор полей определяется общим каталогом показателей.
_Avoid_: Марка продукции, свободный тип продукции

## Отчёты огнеупорного цеха

**Таблица ОЦ**:
Одна из трёх независимых сменных таблиц огнеупорного цеха: ЦОШ, оборудование и выпуск сырца либо печное отделение. Каждая таблица отдельно отправляется и отдельно подтверждается диспетчером.
_Avoid_: Пакет из трёх таблиц, диспетчерская форма

**Дата смены ОЦ**:
Календарная дата начала смены. Первая смена идёт с 08:00 до 20:00, вторая — с 20:00 до 08:00 следующего дня; ночная смена после полуночи сохраняет дату своего начала.
_Avoid_: Дата окончания ночной смены, время отправки

**Ревизия таблицы ОЦ**:
Неизменяемый снимок одной таблицы за дату и смену. Новая отправка после возврата или явного исправления подтверждённой таблицы создаёт следующую ревизию и не перезаписывает предыдущую.
_Avoid_: Обновление строки на месте, черновик браузера

**Ожидание подтверждения таблицы ОЦ**:
Состояние новой ревизии после фиксации в БД и до отдельного решения диспетчера. После commit диспетчерам отправляется краткое Email/MAX-уведомление по отдельным адресным колонкам, а полные значения таблицы остаются внутри защищённой очереди системы.
_Avoid_: Отправка черновика, рассылка полной pending-таблицы

**Подтверждение таблицы ОЦ**:
Отдельное решение диспетчера по pending-ревизии. Подтверждение фиксирует итоговую версию в БД, после commit отправляет полное содержимое таблицы и итоги отдельным Email/MAX-адресатам ОЦ; автор таблицы не может подтвердить её сам.
_Avoid_: Подтверждение всех трёх таблиц одной кнопкой, редактирование диспетчером

**Возврат таблицы ОЦ**:
Решение диспетчера с обязательным комментарием, после которого сохранённые значения снова доступны автору для доработки и повторной отправки новой ревизией.
_Avoid_: Удаление таблицы, исправление диспетчером

**Замер банки ЦОШ**:
Одно измерение длины с доступной стороны банки; для одной банки работник может внести произвольное положительное количество замеров, из которых определяется среднее арифметическое.
_Avoid_: Фиксированные четыре стороны, среднее ручным вводом

**Содержимое банки ЦОШ**:
Текущее назначение конкретной лабораторной пробы банке I, II или III. Объект испытаний пробы задаёт материал, а сохранённый в ней насыпной вес — коэффициент расчёта; новое назначение не удаляет историю предыдущих.
_Avoid_: Марка продукции, ручной коэффициент, изменение старых назначений

**Расчётная масса содержимого банки**:
Произведение объёма из справочного соответствия среднего замера `H·m → м³` на насыпной вес содержимого банки.
_Avoid_: Введённый вручную вес, сумма замеров, пересчёт старой ревизии по новому назначению

## Журнал действий

**Событие аудита**:
Неизменяемая серверная запись о значимом действии вошедшей учётной записи: входе, отправке формы, изменении данных, административном действии или просмотре экрана.
_Avoid_: Лог кликов, история браузера

**Автор действия**:
Реально вошедшая учётная запись, которую сервер определил по сессии; режим административного просмотра другого кабинета не меняет автора.
_Avoid_: Просматриваемый аккаунт, пользователь из клиентского payload

**Отчёт действий пользователей**:
Административное представление событий аудита за последние три календарных месяца с фильтром по отдельной учётной записи и типу действия. Трёхмесячное окно ограничивает только отображение и не является сроком хранения.
_Avoid_: Срок хранения аудита, очистка истории

**Аудируемое изменение**:
Бизнес- или административное изменение, которое фиксируется в одной транзакции с соответствующим событием аудита. Если событие аудита сохранить нельзя, само изменение откатывается; внешние уведомления отправляются только после успешной фиксации транзакции.
_Avoid_: Best-effort аудит, отдельная постфактум запись

**Просмотр экрана**:
Открытие разрешённой основной вкладки или диспетчерской формы, зафиксированное по server-owned списку экранов.
_Avoid_: Каждый клик, focus, движение мыши

## Выработка

**Категория выработки**:
Один из четырёх независимых производственных контуров: формовка, сортировка, неформованная продукция/контейнеры или цех обжига шамота.
_Avoid_: Марка продукции, строка диспетчерской таблицы

**Месячный план категории**:
Положительное количество выработки с точностью не более двух знаков после запятой, которое экономист утверждает для одной категории на один календарный месяц. В форме диспетчера backend показывает read-only накопительный план с первого дня месяца по выбранную дату, включая даты без отправленного отчёта.
_Avoid_: Один общий план завода, сумма планов по маркам, план без категории или месяца

**Рабочий день плана**:
Конкретная дата выбранного месяца, которую экономист подтвердил для одной категории выработки; разные категории могут иметь разные рабочие дни.
_Avoid_: Общий рабочий день всех категорий, порядковый номер без даты

**Пресет расписания**:
Начальный набор дат одной категории: все календарные дни месяца или только понедельник–пятница. После выбора пресета экономист может вручную добавить или убрать любую дату.
_Avoid_: Неизменяемый календарь, автоматически утверждённые рабочие дни

**Ежедневный план категории**:
Распределение месячного плана одной категории по её собственным подтверждённым дням: до предпоследнего дня ставится округлённая вверх целая доля, а на последний день приходится точный остаток с точностью до сотых. В форме диспетчера это read-only значение соответствующей категории.
_Avoid_: Дробные значения до последнего дня, независимые дневные значения, план отдельной марки

**Марка продукции**:
Единая метка из первого столбца `Наименование` вкладки Google Sheets `Номенклатура`. Один и тот же server-gated справочник используется во всех полях марки диспетчерской выработки и огнеупорного цеха; новая марка записывается в первую свободную ячейку столбца A, начиная со строки 2.
_Avoid_: Свободный текст отчёта, отдельный справочник по форме или категории, второй столбец `Вид изделия`, временная клиентская опция

**Каноническая марка**:
Точное написание марки из текущей вкладки `Номенклатура`, которым backend заменяет пользовательский ввод перед сохранением отчёта. Поиск и сопоставление не учитывают регистр и лишние пробелы, но сохранённые отчёты продолжают хранить строковое значение марки как исторический снимок.
_Avoid_: Клиентская канонизация как источник истины, автоматическое изменение старых отчётов, сохранение отсутствующей в номенклатуре марки

**Факт по марке**:
Суточное фактическое количество для одной марки внутри категории; в одном отчёте одна и та же марка категории не повторяется. Аналитика сохраняет суточный и накопленный месячный факт по марке. План категории сравнивается с суммой фактов всех её марок, но не распределяется между марками.
_Avoid_: План марки, повторная колонка той же марки, отдельный месячный план

**Суточный показатель выработки**:
Введённый диспетчером факт за конкретную дату отчёта; план той же даты принадлежит подтверждённому плану категории. Если за одну дату существует несколько отчётов, в расчётных таблицах используется последняя полученная запись за этот день.
_Avoid_: Введённый диспетчером план, месячное значение в форме, сумма повторных отправок за день

**Месячный итог выработки**:
Вычисляемая backend-ом сумма суточных показателей категории с первого дня календарного месяца по дату соответствующего отчёта включительно. Во всех четырёх категориях суточный факт складывается из фактов уникальных нормализованных марок; сами марки сохраняются в строке отчёта для последующей аналитики. В форме ввода backend отдаёт сохранённый итог предыдущих дней, а frontend добавляет ещё не сохранённый факт выбранных суток.
_Avoid_: Введённый вручную месяц, сумма только видимого диапазона, группировка по номеру строки

**Отклонение выработки**:
Разница `месячный факт − накопительный план` с первого дня месяца по выбранную дату включительно. Форма диспетчера сразу пересчитывает её из server-owned плана и месячного факта предыдущих дней с добавлением текущего чернового факта; при редактировании сохранённый факт этих суток заменяется черновым, а не учитывается дважды. Значение остаётся read-only и не входит в отправляемый payload.
_Avoid_: Суточная разница, план минус факт, ручной ввод

**Расход банки**:
Вычисляемая разница между замером в начале дня и замером в конце дня для одной банки: `начало дня − конец дня`.
_Avoid_: Конец минус начало, отдельное поле ручного ввода расхода
