# Интеграция с 1С: приём отчёта об остатках

Первый этап интеграции: 1С по расписанию отправляет в НМОУ Вектор выгрузку
остатков по складу, сайт показывает её во вкладке `Склад 1С` в разрезе
номенклатуры. Движение по складу за период — следующий этап.

Контактное лицо со стороны 1С: Мантей Александр, `it-ogneupor@yandex.ru`.

## Конечная точка

| Окружение | URL |
| --- | --- |
| TEST | `https://test.smb.aonmou.ru/api/upload-report` |
| PRODUCTION | `https://smb.aonmou.ru/api/upload-report` |

- Метод: `POST`.
- Заголовок: `x-api-key: <ключ>`. Значение задаётся на сервере переменной
  `ONEC_UPLOAD_API_KEY` в непубличном `server/.env` и совпадает с `API_KEY`
  отправителя. Минимальная длина — 16 символов. Пока переменная не задана,
  эндпоинт отвечает `503` и ничего не принимает.
- Тело: `multipart/form-data`.

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| `file` | да | Файл отчёта, только `.xlsx` |
| `timestamp` | нет | Время отправки; сохраняется как есть, до 40 символов |
| `source` | нет | Отправитель; сохраняется как есть, до 120 символов |

Ограничение размера — 20 МБ. Формат `.xls` не принимается: отчёт нужно
выгружать в `.xlsx`.

## Формат отчёта

Проверено на реальной выгрузке `Сводный отчёт по материалам и готовой
продукции` (`report_20260824_104017.xlsx`, 73 строки по счёту 43 и 31 по счёту
10.01):

```
Сводный отчёт по материалам и готовой продукции
Период: 23.08.2026 - 23.08.2026
Всего записей по сч.43: 73, по сч.10.01: 31

Счёт 43 (Готовая продукция)
Счет | Номенклатура | Ост.Дебет нач. | Ост.Кредит нач. | Оборот Дебет | Оборот Кредит | Ост.Дебет кон. | Ост.Кредит кон.
43   | ШБ-15 кер    | 594 262,58     | 0               | 0            | 0             | 594 262,58     | 0
...

Счёт 10.01 (Материалы)
Счет  | Номенклатура           | ...
10.01 | Огнеупорлом дробленый  | 1 836,24 | ...
```

Один файл содержит **несколько счетов**, каждый своей секцией со своей шапкой
колонок. Сервер сохраняет отдельный отчёт на каждый счёт — все в одной
транзакции, поэтому наполовину загруженного файла не бывает.

## Что сервер читает из файла

Дата остатков и счета не передаются параметрами — их определяет сам отчёт:

- **Дата.** Ищется в шапке над первой таблицей: `дд.мм.гггг`, `гггг-мм-дд`,
  `23 августа 2026` и ячейки с датным форматом Excel. Если дат несколько
  (`Период: 01.08.2026 - 23.08.2026`), берётся самая поздняя: конечный остаток
  относится к концу периода.
- **Счёт строки.** Берётся из колонки `Счет`. Если колонки нет — из последнего
  заголовка секции `Счёт 43 (Готовая продукция)`, а если нет и его — из шапки
  файла.
- **Подпись счёта.** Берётся из заголовка секции целиком, поэтому фильтр
  показывает ровно то, как счёт назван в выгрузке. Зашит только `Счёт 43
  (Готовая продукция)` — чтобы фильтр не был пустым до первой загрузки.
- **Остатки.** Берутся дебетовые колонки `Ост.Дебет нач.` и `Ост.Дебет кон.`:
  на счетах 43 и 10.01 сальдо активное, и 1С сама сворачивает его в дебет —
  отрицательный остаток приходит туда со знаком минус (`-2 045,53`).
  Кредитовые колонки и обороты в разрез не попадают.
- **Числа.** Приходят текстом с неразрывными пробелами между разрядами и
  запятой в дроби; хранятся как `decimal(18,3)`.
- **Пропуск строк.** `Итого`, `Всего`, `Обороты` и строки без наименования.
  Повтор наименования считается в пределах счёта: `ГАС-порошок` законно
  присутствует и в 43, и в 10.01.

Поддерживаются и другие подписи колонок (`Ост. нач.`, `Сальдо на начало/конец
периода`, `Остаток на начало/конец`), в том числе разнесённые на две строки.
Полный список — в `server/src/domain/warehouse1cStockReport.ts`; добавление
нового варианта заголовка не затрагивает остальной разбор.

## Ответы

| Код | Когда |
| --- | --- |
| `200` | Отчёт принят; в теле `success`, `reportDate`, `rows` и `reports` — по элементу на счёт с `accountCode`, `rows`, `replaced` |
| `400` | Файл не передан |
| `401` | Неверный или отсутствующий `x-api-key` |
| `413` | Файл больше 20 МБ |
| `415` | Не `multipart/form-data` или файл не `.xlsx` |
| `422` | Файл не разобрался; в сообщении об ошибке приводятся первые строки листа |
| `503` | Ключ интеграции не задан или БД недоступна |

Повторная отправка отчёта за ту же дату и тот же счёт заменяет предыдущую
загрузку целиком (`replaced: true`): 1С присылает срез остатков, а не
приращение. Счета в файле независимы: если в новой выгрузке пропал счёт,
прежний его отчёт остаётся нетронутым.

## Как данные показываются на сайте

Вкладка `Склад 1С` читает `GET /api/warehouse-1c/stock-balances` с
необязательными `accountCode` и `reportDate`. Фильтр `Счёт` показывает все
счета, которые встретились в загруженных выгрузках; по умолчанию открывается
`Счёт 43 (Готовая продукция)`, даже если по номеру он не первый. Доступ даёт capability
`business.view_warehouse_1c`, которую администратор выдаёт должности вместе с
вкладкой. Приёмник отчётов сессию не использует — он работает только по ключу.

## Проверка вручную

```bash
curl -sS -X POST https://test.smb.aonmou.ru/api/upload-report \
  -H "x-api-key: $ONEC_UPLOAD_API_KEY" \
  -F "file=@Остатки.xlsx" \
  -F "timestamp=$(date -Iseconds)" \
  -F "source=manual-check"
```
