# Таблицы, истории и журналы

Также читать `docs/table-layouts.md`. Для UI применять [ui.md](ui.md).

- Все таблицы подключать через `ManagedTable`, ячейки — через `TableCell`/`TableHeader`/`AriaTableCell`; идентификаторы и допустимые колонки брать из `server/src/contracts/tableLayouts.ts`. Условные и динамические колонки передавать явно в порядке отображения, использовать смысловые ID, а не подписи или позиции. Размеры хранить server-owned с ревизией и аудитом; право `platform.manage_table_layouts` проверять по настоящему профилю сессии, независимо от preview. Подробнее: `docs/table-layouts.md`.

- Совокупный текст ячейки ограничивать четырьмя строками с переносом; полное переполненное значение показывать общей подсказкой. Поля ввода и управляющие элементы сохранять рабочими. Сброс ширин должен затрагивать только видимые колонки, сохраняя настройки других вариантов того же типа таблицы. Не добавлять отдельные обработчики перетаскивания или серверные запросы на каждую ячейку.

- Все текущие и будущие табличные представления истории и журналов должны использовать общий контейнер `history-table-scroll`: ограничивать высоту таблицы, прокручивать её содержимое независимо от страницы по обеим осям и закреплять весь `thead` сверху. В ARIA-таблицах строка с `role="columnheader"` получает общий маркер `history-table-head`. Живые реестры и формы ввода не переводить на этот режим автоматически.

- При создании или доработке любой истории и любого журнала сортировать записи по основной дате и времени события по убыванию, чтобы самые свежие находились сверху. Иной порядок использовать только по явному требованию конкретного журнала.
