# Общий интерфейс

- В React-обработчиках сначала синхронно копировать нужные `event.currentTarget.value`/`checked` в локальную переменную и только затем вызывать функциональный `setState`; запрещено читать `event.currentTarget` внутри callback вида `setState((current) => ...)`, потому что отложенное выполнение уже приводило к падению рендера и белому экрану.

- Все компактные модальные окна на `admin-db-modal-backdrop` должны закрываться только при нажатии на сам фон: нажатие внутри окна не закрывает его, а во время сохранения или другого выполняющегося изменения закрытие снаружи блокируется тем же guard, что и кнопка отмены.

- Мобильные модальные окна должны ограничивать высоту относительно внутренней области backdrop после его отступов, а не напрямую через `vh`: иначе центрированное окно обрезается одновременно сверху и снизу на низком viewport или при открытой экранной клавиатуре. Верхний и нижний отступы backdrop обязаны учитывать `safe-area-inset-top` и `safe-area-inset-bottom`.

- Общую навигацию рабочего app shell держать единой для всех кабинетов и адаптивной: на desktop/горизонтальном интерфейсе левый rail всегда открыт, логотип статичен и кнопка скрытия панели отсутствует; на mobile по умолчанию остаётся компактная верхняя панель с логотипом и кнопкой меню справа, которая открывает drawer слева поверх страницы. Мобильное меню должно закрываться после выбора раздела, по кнопке закрытия внутри drawer, по клику на затемнение и по `Escape`, удерживать клавиатурный фокус внутри до закрытия и использовать `aria-expanded`/`aria-controls`; не создавать отдельные role-specific реализации навигации.

- Подтверждения успешных действий во всех кабинетах показывать через общий фиксированный toast-стек в правом нижнем углу поверх страницы, а не inline-блоком в потоке документа: появление уведомления не должно менять высоту контента или позицию прокрутки. При фоновом обновлении после такого действия сохранять уже показанный список или таблицу до получения нового ответа, чтобы временный loading-state не схлопывал страницу; состояния загрузки, ошибки и подсказки валидации оставлять рядом с соответствующим действием.

- Toast-уведомления всегда получают явный семантический тип: `warning` отображается красным для предупреждений, ошибок, просрочки и возврата на доработку; `suggestion` — жёлтым для предложений, напоминаний и ожидающих внимания действий; `success` — зелёным для приветствий, информационных подтверждений и успешно выполненных действий. Автоматически через четыре секунды закрывать все и только `success`; `warning` и `suggestion` оставлять до ручного нажатия на крестик. При удалении карточки оставшиеся уведомления должны плавно занимать освободившееся место; для FLIP-анимации фиксированного снизу стека сравнивать экранные координаты `getBoundingClientRect()`, а не локальный `offsetTop`. Не определять тип по тексту заголовка или сообщения.

- Первичную загрузку страницы, раздела, формы, справочника или доступа и ожидание отправки показывать через общий `LoadingIndicator` с размером по контексту, короткой понятной подписью и `role="status"`; не создавать отдельные спиннеры для каждого экрана и обязательно отключать движение через `prefers-reduced-motion`.

- Все уведомления, тосты, ошибки и статусные подсказки для неадминистративных пользователей должны быть максимально короткими и понятными: без id отправок, endpoint, CORS, `/health`, `localStorage`, remote/backend/server/feed и другой технической диагностики. Технические детали допустимы только в админских инструментах, логах, тестах и инструкциях настройки.

- Экран входа является самостоятельным прокручиваемым контейнером и после обычного открытия или восстановления страницы должен начинаться сверху. Safari может восстановить `scrollTop` вложенного `.auth-shell` уже во время `pageshow`, после следующего animation frame или при последующей загрузке server-backed карточек доступа, поэтому lifecycle экрана должен временно удерживать верхнюю позицию и отпускать защиту сразу после реального пользовательского `wheel`/touch/pointer/keyboard-ввода; одного `window.scrollTo`, CSS-высоты или однократного animation frame недостаточно. Jino должен отдавать HTML с `Cache-Control: no-cache, no-store, must-revalidate`, чтобы Safari после deploy заново получил ссылки на актуальные hashed assets.

- Визуальный стиль проекта: Industrial Finance Operations — светлый stone-gray рабочий интерфейс с blue-gray навигацией, compact density, server/status strip, очередями, таблицами и строгими статусными цветами.

- Видимый бренд продукта — `НМОУ Вектор`; основной брендмарк хранится в `public/nmou-vector-icon.png`, а favicon и Apple Touch Icon являются его прозрачными уменьшенными версиями. Заголовок вкладки production — `Вектор`, test — `Вектор Тест`. Технические идентификаторы `smb-*`, env-переменные, package names, storage keys и deployment-пути не переименовывать вместе с видимым брендом, чтобы не ломать окружения и сохранённые данные.

- Крупные отдельные рабочие разделы подключать из `App.tsx` через `React.lazy` и динамический import. Не возвращать статические импорты этих разделов в стартовый граф. `WorkspaceBoundary` охватывает только рабочую область: навигация доступна при загрузке/ошибке, индикатор — общий `LoadingIndicator`; смена раздела/аккаунта сбрасывает ошибку. Библиотеки React выделены в `react-vendor` средствами установленного Rolldown; предупреждение о размере не скрывать повышением лимита.

- Горизонтальной прокрутки на сайте нет нигде, кроме широких таблиц: на экране от 360 px всё остальное помещается по ширине — поля, кнопки и вкладки переносятся или сужаются. Таблица прокручивается только внутри своего `ManagedTable`: контейнер `.managed-table-scroll` имеет `contain: inline-size` (ширина таблицы не поднимается вверх и не растягивает разделы) и `position: relative` (абсолютные элементы ячеек, например скрытые подписи, не расширяют страницу). Не снимать эти свойства и не выносить таблицу из `ManagedTable` в собственный контейнер прокрутки. Сетки, в которых окажется таблица или длинное содержимое, задают колонки `minmax(0, 1fr)`, а не неявную `auto`; адаптивные сетки — `repeat(auto-fit, minmax(min(100%, Npx), 1fr))`; вне таблиц не ставить `width`/`min-width` больше ширины узкого экрана; ряды кнопок и вкладок — с переносом. После изменения вёрстки запускать `npm run check:layout` при запущенных `npm run dev:api` и `npm run dev:web -- --host 127.0.0.1`: скрипт входит под каждой должностью с экрана «Выбор доступа» (на копии production — весь настоящий каталог; должности с уже проверенным меню на той же ширине проверяются только по стартовому экрану), обходит меню, внутренние вкладки, кнопки открытия форм и первую строку таблиц (карточки и окна записей) в окнах 375, 820, 1024 и 1280 px (ключ `--widths`, каждая ширина — параллельный процесс), блокирует в браузере все запросы кроме GET и перечисляет контейнеры, переполненные не таблицей, элементы за правым краем и схлопнутые таблицы. Для обычной задачи ограничивать обход затронутыми вкладками (`--rail`) и должностями (`--positions`), полный обход — для изменений общей вёрстки. `--preview 1` проходит по одному настоящему аккаунту каждой должности через предпросмотр администратора — для личных экранов (мои поручения, временные роли). `--trace <селектор>` печатает цепочку вычисленных стилей от элемента вверх.

- Медиа-запросы содержимого разделов срабатывают по ширине области содержимого, а не окна: левое меню занимает 230 px при окне 821–1180 px и 276 px шире. Порог содержимого `X` до 590 px пишется как есть; 591–820 px — `(max-width: X), (min-width: 821px) and (max-width: X+230)`; 821–950 px — `(max-width: X+230)`; от 951 px — `(max-width: X+276)`. Запросы оболочки и меню (820 и 1180 px) остаются по ширине окна. `container-type` для рабочей области не использовать: модальные окна рендерятся внутри неё, а старые Safari ограничивают `position: fixed` контейнером.
