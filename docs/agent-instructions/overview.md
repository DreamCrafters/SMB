# Руководительский обзор и диспетчерская

Также читать правила отображаемого источника: выработка — [production.md](production.md), банки — [refractory.md](refractory.md), оборудование/инциденты/посетители — [dispatcher.md](dispatcher.md).

- `Обзор` владельца должен сохранять компактные блоки оборудования, выработки, банок и последних посетителей. Плитка `Банки` стоит последней перед `Посетителями`, показывает три банки в ряд с текущим содержимым и остатком по замерам и по отгрузкам и по клику открывает `Диспетчерская → Выработка → Замеры банок`. Остаток брать из последней server-owned строки замеров банки как есть, а содержимое — из текущего назначения Лаборатории; плитка доступна всем, у кого есть `Диспетчерская`, и тумблером посетителей не ограничивается. Выбранный раздел `Выработки` хранить в фильтрах диспетчерской ленты, а не в локальном состоянии таблицы, чтобы переход из `Обзора` открывал нужную таблицу. Server-owned сводка считает за текущий месяц и сегодня: лабораторные результаты, отобранные пробы, химические анализы и показания `Журнала печи 2`; формовку, сортировку, неформованную продукцию, шамот и грануляцию. Грануляция складывает две действующие фракции `16/30` и `12/18`, а новый месяц без записей начинается с нулей. Посетителей строить из общей сохранённой dispatcher-истории: выход сначала связывать по server-owned ID, а если такого входа нет — по нормализованной паре ФИО + организация для legacy-данных; существующую корректную ID-связь этим fallback не заменять. Старые подробные карточки последнего открытия и последнего закрытия инцидента не возвращать: их заменяет новая сводка `Инциденты`, а детали остаются во вкладке `Диспетчерская`. Закрытие инцидента по-прежнему должно получать тип и место из server-owned payload либо связанного открытия с тем же номером; backend обязан переносить оба значения в payload новых закрытий.

- Вкладка владельца `Диспетчерская` должна показывать 4 раздела, а не сырую форму-фильтрацию: расчётные таблицы выработки, агрегаты оборудования, объединённый список открытия/закрытия инцидентов с незакрытыми к началу периода и список посетителей. Внутри выработки держать отдельные кнопки-таблицы для формовки, сортировки, неформованной продукции, цеха обжига шамота, замеров банок и участка грануляции; дата строки открывает полный дневной отчёт. Все разделы используют единый выбор периода `Сегодня`, `Текущий месяц`, `Текущий год`, `Своё`; месяц и год считаются от начала периода по сегодняшний день, а `Своё` по умолчанию оставляет обе даты пустыми и показывает данные за всё время. История владельца должна автоматически дочитываться страницами через backend, а не молча обрезаться лимитом одной страницы; периодический polling после полной загрузки обновляет только последнюю страницу и повторяет полный проход лишь при рассинхронизации количества записей.
