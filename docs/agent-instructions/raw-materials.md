# Склад сырья

Обязательно читать [laboratory.md](laboratory.md).

- В `Лаборатория → Склад сырья` новую заявку может создавать любая должность с capability `business.manage_laboratory_results`. Право не привязывать к коду должности: созданные администратором должности получают id вида `position-<uuid>`, поэтому проверка по системному коду не даёт форму никому, кроме одной посеянной должности. Заявка server-owned остаётся ожидающей и не входит в историю или итоги до решения кладовщика. Назначение кладовщику права проверки хранить отдельным server-owned признаком должности `can_review_raw_material_warehouse`, а его эффективный доступ — capability `business.review_raw_material_warehouse`: временное выключение лабораторной вкладки не должно терять назначение, но при выключенной вкладке capability не выдаётся. Не выводить право на каждом запросе из отображаемого названия должности и не совмещать с общим `business.manage_laboratory_results`: кладовщик видит только склад, может подтверждать и исправлять, но не создаёт заявки и не изменяет остальные лабораторные журналы. Один пользователь не может подтвердить свою заявку через другой доступ. Подтверждение и каждое исправление добавляют append-only ревизию со статусом и именем кладовщика из активной сессии, а история показывает без скрытого лимита только последнюю утверждённую или скорректированную версию стабильной записи. Вид сырья на складе выбирать только из server-owned `Номенклатура → Сырьё`: backend канонизирует подпись по текущему списку и отклоняет отсутствующее значение, а новое сырьё добавляется через профильный журнал номенклатуры. Сырьё не смешивать с `Журналом марок`. Штабель, поставщик и получатель остаются свободным вводом с накапливаемыми подсказками из истории склада. Суммы и фильтры считать на backend.
