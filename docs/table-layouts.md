# Настройка колонок таблиц

Администратор меняет ширины через «Настроить колонки» рядом с таблицей.
Перетаскивание границы заголовка показывает результат сразу, но сохраняет его
только по кнопке «Сохранить». В «Точная ширина» можно ввести число и применить
его Enter или выходом из поля. Поля ширины связаны с отдельной служебной формой
и не участвуют в проверке и отправке бизнес-формы. Граница управляется также стрелками, Home и End;
Escape отменяет текущее перетаскивание. «Отмена» возвращает сохранённые ширины.

Настройки общие для экземпляра сайта. Пользователь получает их после входа или
перезагрузки страницы. Сохранение обновляет все экземпляры той же таблицы в
открытой сессии администратора. Фоновая рассылка изменений другим браузерам не
используется. «Сбросить ширины» возвращает исходные размеры только показанных
колонок; требуется «Сохранить». Скрытые колонки и другие представления сохраняют
свои настройки.

Текст переносится в пределах колонки и ограничен четырьмя строками. Полное
значение переполненного текстового блока доступно при наведении на ячейку,
фокусе на её действии или нажатии на текст на сенсорном устройстве. Подсказка
позволяет выделять и копировать текст и закрывается Escape. Текстовые действия
вроде ссылки на поручение остаются рабочими; ввод, списки, кнопки управления и
явно раскрываемые вложенные журналы не обрезаются вместе с текстом.

## Общий контракт и подключение

`server/src/contracts/tableLayouts.ts` — реестр 50 типов таблиц, их смысловых
колонок и ограничений; он используется сервером и frontend без React-зависимости.
Все 52 места табличной разметки подключены к `ManagedTable`. Общие таблицы замеров
повторно используются формой сырья и формой сырцовой продукции.

- `TableId` ограничен ключами реестра, `TableColumnId<TableId>` — колонками выбранной
  таблицы. Для условных колонок явно передавать показанный список в порядке
  разметки, например `columns={["nomenclature", "closingQuantity"]}`.
- Колонки лабораторных журналов берутся из существующих контрактов полей.
  Химические анализы в дочерних журналах имеют префикс `analysis.`, чтобы не
  смешиваться с одноимёнными собственными полями пробы.
- Динамические колонки имеют ограниченные семейства: `brand.<номер>` для слотов
  формы выработки, `indicator.<id>` для показателей, `field.<таблица>.<поле>` для
  редактора БД и `column.<номер>` для исходного листа Excel. В последнем случае
  номер означает физическую координату листа, а не бизнес-поле.
- Один тип таблицы использует общий стиль при повторном отображении. Разные
  наборы замеров разделяются идентификаторами полей; таблицы редактора БД —
  префиксом имени таблицы. Не использовать подпись, индекс видимой колонки,
  имя пользователя или номер записи в качестве ключа бизнес-колонки.
- `ManagedTable` сохраняет существующие типизированные строки и обработчики.
  HTML использует `colgroup`, CSS Grid — тот же набор ширин через CSS-переменные.
  Объединённые заголовки вычисляются по `rowSpan`/`colSpan`; меняются конечные
  колонки, ширина группы является их суммой. Подпись заголовка с интерактивным
  содержимым задаётся через `data-table-column-label`.
- `TableCell`, `TableHeader`, `AriaTableCell` применяют общие правила текста.
  Не заменять их обычными `td`/`th` или ARIA-ячейками. Проверка каталога в
  `tests/tableCatalog.test.mjs` контролирует эту границу.
- Для историй сохранять `history-table-scroll`. Ограничение высоты и обе оси
  прокрутки находятся на вложенном `managed-table-scroll`; исходный внешний
  контейнер сохраняет оформление. Формы с полной высотой не ограничиваются
  как журналы автоматически.

## Сервер и права

`GET /api/table-layouts` требует сессию и возвращает сохранённые настройки и
`canManage`. `PUT /api/table-layouts` принимает `tableId`, `revision`, `widths`.
Сохраняются только отличия от начальных размеров, в целых пикселях, в диапазоне
64–960. Максимум 512 переопределений в записи. Произвольные CSS и HTML не
принимаются; пользовательский текст в подсказках выводится как текст React.

Право `platform.manage_table_layouts` выдаётся системному администратору и
должностям с правами админа. Обработчик проверяет настоящий профиль сессии через
`readSignedInAccess`: предпросмотр должности не даёт это право обычному
пользователю и не лишает его настоящего администратора. Настройка размеров не
меняет доступ к самим данным или бизнес-действиям.

Таблица `app_table_layouts` хранит версию и JSON ширин по `table_id`. При записи
создаётся блокируемая строка, затем проверяется версия под `FOR UPDATE`.
Сохранение и событие `admin.table_layout_update` с before/after выполняются
через общий `runAuditedMutation`. Устаревшая версия получает `409`; интерфейс
предлагает загрузить актуальные настройки. Ошибка аудита откатывает запись.

Если хранилище недоступно, таблицы показывают исходные размеры; администратор
может повторить загрузку. Обновление геометрии во время перетаскивания выполняется
через `requestAnimationFrame` и CSS-переменные без запросов на сервер и изменения
React-состояния строк на каждом движении. Подсказка одна на страницу; переполнение
измеряется только при взаимодействии с ячейкой.

## Обновление и проверка

После обновления кода выполнить штатную миграцию `081_table_layouts`
(`npm run db:migrate`), собрать frontend/backend и перезапустить backend.
Новые env-переменные и зависимости не нужны.

Если применение `081_table_layouts` остановилось с `Unknown column 'code' in
'WHERE'`, обновить код с исправлением обращения к `account_positions.id` и
повторить `npm run db:migrate`. Удалять созданную `app_table_layouts` или вручную
помечать миграцию выполненной не нужно: создание таблицы использует `IF NOT
EXISTS`, добавление права защищено от дублей, а отметка выполнения записывается
только после всех SQL-запросов.

Автоматические проверки: контракт ширин и каталога, права API с поддельным
preview-заголовком, конфликт версий, откат при ошибке аудита, миграция прав,
сохранение/отмена/сброс видимых колонок, условные и объединённые заголовки,
сохранность полей и действий, показ полного текста, отсутствие обычных
таблиц в обход общего модуля. Полные команды: `npm test`, `npm run typecheck`,
`npm run build`, `git diff --check`.

Перед выпуском дополнительно проверить в реальном браузере длинный текст,
перетаскивание мышью и касанием, узкий экран, масштабирование, закреплённые
заголовки и первые колонки, раскрытие лабораторных замеров и формы оборудования.
На MariaDB проверить сохранение из двух администраторских сессий. JSDOM не
проверяет пиксельную геометрию, а тестовый репозиторий не заменяет живую БД.
