# Google Sheets как источник справочников

Сейчас backend читает Google Sheets для полей диспетчерской формы:

- форма: `Открытие инцидента`
- поле: `Место (цех/участок)`, колонка в таблице: `Места (цех/участок)`
- поле: `Ответственный за регистрацию`, колонка в таблице: `Ответственный за регистрацию`
- email-адресаты подтверждённых таблиц огнеупорного цеха, колонка в таблице: `Адресаты ОЦ (емейлы)`
- MAX ID адресатов подтверждённых таблиц огнеупорного цеха, колонка в таблице: `Адресаты ОЦ (МАКС)`
- email-адресаты диспетчеров для новых таблиц огнеупорного цеха, колонка в таблице: `Адресаты Диспетчеры (емейлы)`
- MAX ID диспетчеров для новых таблиц огнеупорного цеха, колонка в таблице: `Адресаты Диспетчеры (МАКС)`

Персональные Email и MAX пользователей не импортируются из Google Sheets. Они хранятся в `app_users` и заполняются администратором на сайте во вкладке `Учётные записи → Уведомления`; server-owned настройки пользователя определяют доступные ему каналы. Колонки адресатов инцидентов, посетителей, оборудования и выработки больше не являются production-источником, а отдельные групповые колонки огнеупорного цеха пока сохраняют прежнее назначение.

Текущая ссылка по умолчанию:

```text
https://docs.google.com/spreadsheets/d/1JYz_03AW4j9VXNfdNSBFfdFyxq0Dun_0QnYGvVesGyg/edit?gid=981703922#gid=981703922
```

## Номенклатура марок больше не зависит от Google Sheets

Начиная с миграции `050_product_brand_journal`, марки хранятся в server-owned таблице MariaDB/MySQL и управляются в разделе `Лаборатория → Марки`. Миграция один раз переносит 119 наименований из прежнего столбца `Номенклатура!A:A`; столбец `Вид изделия` не переносится в новое поле `Класс`, потому что это разные характеристики.

В журнале обязательным остаётся только `Наименование`. Поля `Описание`, `Класс`, `Отрасль применения`, `Норматив (ГОСТ, ТУ)`, `Геометрия Д*Ш*В`, `Al2O3`, `Fe2O3` и `Прочность` необязательны. Создание и исправление доступны только через лабораторную вкладку, сохраняют стабильный идентификатор, ревизию и обязательное audit-событие.

Все поисковые поля марки по-прежнему получают единый список через `GET /api/production-brands`, но этот endpoint теперь читает MariaDB/MySQL и не обращается к Google Sheets. `POST /api/production-brands` отключён; производственные формы больше не создают марки. Уже сохранённая в отчёте строка остаётся историческим снимком, а новая отправка проходит server-side проверку по текущему журналу.

Backend умеет читать Google Sheets двумя способами:

- `public_csv` — обычная Google Sheets ссылка превращается в CSV-export ссылку; таблица должна быть публично читаемой.
- `service_account` — таблица остаётся закрытой, а backend читает её через Google Sheets API от имени service account.

## Номенклатура сырья больше не зависит от Google Sheets

Начиная с миграции `074_initial_raw_material_nomenclature`, сырьё хранится в server-owned таблице `laboratory_raw_material_nomenclature` и управляется в разделе `Лаборатория → Номенклатура → Сырьё`. Миграция один раз переносит 69 наименований с вкладки `Сырьё` той же книги; повтор наименования пропускается, поэтому уже добавленное в системе сырьё она не трогает. После миграции приложение эту вкладку не читает: новые наименования добавляются только в журнале.

Поле `Вид сырья` в `Лаборатория → Склад сырья` получает раскрывающийся список напрямую из этой server-owned номенклатуры; значение вне текущего списка backend отклоняет. Новое сырьё сначала добавляют в `Номенклатура → Сырьё`. Штабели, поставщики и получатели по-прежнему накапливаются отдельно из истории движений склада.

## Матрица лабораторных испытаний

Вкладка `Лаборатория` той же книги является server-owned источником формы `Результаты испытаний`. Backend читает её отдельным запросом и ожидает таблицу, в которой:

- первые две колонки называются `Раздел` и `Материал`;
- строка `Ссылка на ГОСТ` содержит подписи стандартов под колонками показателей;
- строки раздела `Готовая продукция` формируют список видов готовой продукции;
- строки раздела `Сырье` формируют профили для печатного протокола;
- непустая отметка в колонке показателя добавляет этот показатель в PDF-протокол соответствующего профиля сырья или готовой продукции.

Поддерживаемые колонки показателей: `Al2O3`, `Fe2O3`, `SiO2`, `CaO2`, `P2O5`, `ппп`, `Влажность`, `Насыпной вес`, `Водопоглощение`, `Прочность`, `Зерновой состав`. Frontend получает безопасный справочник через `GET /api/laboratory/reference` и не обращается к Google Sheets напрямую. Все поддерживаемые показатели всегда открыты для ввода, каждое поле необязательно само по себе. Цель испытаний и примечание к протоколу обязательны в обоих разделах, а цель открыта для редактирования с готовым начальным значением. Во входящем контроле `Объект испытаний` вводится свободным текстом, а один отчёт содержит одну или несколько проб: у каждой обязательны собственный номер пробы или идентификатор транспорта и хотя бы один показатель. При отправке backend повторно читает актуальный каталог и отклоняет пустую пробу либо показатель вне каталога до начала DB-транзакции.

Отметки матрицы не скрывают поля формы: все поддерживаемые показатели остаются открытыми и необязательными. Для свободно введённого объекта входящего контроля backend выбирает самое длинное название профиля, которое входит в название объекта без учёта регистра, например `Глина марки ГИМ-2` использует профиль `Глина`. Если профиль не найден, в протокол входят фактически заполненные показатели. Заполненный показатель, отсутствующий в выбранном профиле, также добавляется в протокол, чтобы введённый результат не потерялся.

Для раздела готовой продукции матрица задаёт список видов продукции и условные строки их протоколов, а поле `Марка` использует server-owned `Журнал марок` через `/api/production-brands`. При сохранении результата backend записывает снимок текущих показателей, ГОСТов и профилей внутрь payload `laboratory_results`; последующие изменения матрицы не меняют PDF уже сохранённых результатов. Защищённый `GET /api/laboratory/results/:id/protocol.pdf` формирует PDF для открытия, печати или скачивания. Legacy-запись без снимка использует актуальную матрицу.

## Справочник объёма банок

Вкладка `Банки` той же книги содержит server-owned таблицу для расчёта массы материала в банках ЦОШ. Backend использует первые две колонки:

- `A1` — `H·m`, ниже идут значения среднего замера в метрах;
- `B1` — `M3`, ниже идут соответствующие объёмы в кубических метрах;
- строки должны быть отсортированы по возрастанию `H·m`, значения не могут быть отрицательными;
- поддерживаются точка и запятая как десятичный разделитель;
- между соседними строками backend применяет линейную интерполяцию.

Колонки материала и насыпного веса на этой вкладке в расчёте не используются. Текущее содержимое банки и коэффициент насыпного веса берутся только из конкретного результата `Контроля готовой продукции`, который лаборант назначил банке во внутренней вкладке `Банки`: марка результата становится названием содержимого, а вид продукции сохраняется как источник. Результаты `Входящего контроля` для назначения банок не используются; созданные ранее назначения из этого раздела остаются в истории, но больше не считаются текущими. При отправке `Сводки по ЦОШ (ежесменная)` backend заново читает справочную таблицу, рассчитывает все три банки и сохраняет полный расчётный снимок ревизии; последующая смена содержимого банки не меняет старый отчёт.

## Импорт исторических диспетчерских таблиц

В административной вкладке `БД` есть отдельный двухшаговый импорт книги Google Sheets в существующий журнал `dispatcher_submissions`. Импорт принимает книгу с точными вкладками:

- `Оборудование`
- `Инциденты` — используется исходная вкладка, а не `Инциденты(просмотр)`
- `Посетители`

Администратор вставляет ссылку и сначала нажимает `Проверить таблицу`. Все импортируемые записи относятся к единственной организации текущего deployment-а; выбирать отдельный контур данных не нужно. Предпросмотр показывает количество исходных строк, создаваемых записей, уже существующих записей, пропусков и предупреждений. До кнопки `Перенести в БД` база не меняется. Если книга изменилась после предпросмотра, backend отклоняет перенос и требует проверить её заново.

Одна строка оборудования создаёт одну запись `equipment`. Строка инцидента создаёт открытие `incident` и, когда заполнена дата закрытия, отдельное `incident_close`. Строка посетителя создаёт вход `visitor` и, когда заполнено время выхода, связанный `visitor_exit`. Исторические даты записываются в `submitted_at` и `received_at`; для числовых дат Google Sheets используется часовой пояс Москвы. Импорт не отправляет email/MAX-уведомления.

Повторный перенос безопасен: одинаковые записи схлопываются по нормализованному содержимому внутри одной книги ещё до записи в БД. `import_source_key` защищает повторный импорт того же источника, а общий для импорта и обычных диспетчерских форм `dedupe_key` не допускает такую же запись из копии книги, параллельного импорта или одновременной live-отправки. Для оборудования совпадением считаются дата отчёта и оборудование; для открытия/закрытия инцидента — тип записи и номер инцидента; для входа/выхода посетителя — тип записи, соответствующее время, ФИО и организация. `insert ignore` не перезаписывает уже сохранённые production-строки. Миграции `014_dispatcher_spreadsheet_import_source` и `017_single_organization_scope` должны быть применены до первого переноса.

Для закрытой книги не нужно менять `GOOGLE_SHEETS_REFERENCE_URL`, но книге нужно выдать `Viewer` тому же service account, который указан в `GOOGLE_SERVICE_ACCOUNT_KEY_FILE`. Backend читает только URL вида `https://docs.google.com/spreadsheets/d/...` и только три ожидаемые вкладки. Это read-only правило относится к историческому импорту; права `Editor` для марок больше не нужны.

Ожидаемый предпросмотр исходной книги `Диспетчеры` на момент первичного переноса:

- `Оборудование`: 447 исходных строк, 447 записей;
- `Инциденты`: 42 исходные строки, 75 записей;
- `Посетители`: 25 исходных строк, 50 записей;
- всего: 572 записи до вычета уже существующих.

Legacy-нарушения текущих правил формы показываются как предупреждения, но не уничтожают исторические строки. Структурная ошибка — отсутствующая вкладка или колонка, неверная дата/идентификатор ключевой строки — блокирует или пропускает конкретную строку и явно отображается в предпросмотре.

## Требования к структуре таблицы

1. В нужном листе должны быть колонки с заголовками `Места (цех/участок)` и `Ответственный за регистрацию`.
2. Значения должны идти под каждым заголовком до первой пустой строки.
3. Если в одном листе несколько таблиц, backend ищет все колонки с таким заголовком и объединяет найденные значения без дублей.
4. Двоеточие в конце заголовка допустимо: `Ответственный за регистрацию:` и `Ответственный за регистрацию` считаются одним заголовком.

## Требования к адресатам уведомлений

Персональные адресаты уведомлений по инцидентам, посетителям, оборудованию и выработке настраиваются только на сайте через `Учётные записи → Уведомления`. Backend выбирает Email/MAX из `app_users` и server-owned матрицы `user_notification_settings`; Google Sheets не является production-источником этих контактов и не импортирует их в учётные записи.

Для таблиц огнеупорного цеха используются четыре отдельные колонки. Сразу после сохранения новой pending-ревизии backend читает строки `2–20` колонок `Адресаты Диспетчеры (емейлы)` и `Адресаты Диспетчеры (МАКС)` и отправляет диспетчерам краткое уведомление с видом таблицы, датой, сменой, ревизией и мастером. После подтверждения backend читает строки `2–20` колонок `Адресаты ОЦ (емейлы)` и `Адресаты ОЦ (МАКС)` и отправляет полное содержимое конкретной таблицы и рассчитанные итоги. Длинная подтверждённая таблица для MAX автоматически делится на нумерованные части без обрезания строк. Возврат на доработку остаётся внутренним уведомлением аккаунта ОЦ и внешним адресатам не рассылается.

В групповых MAX-колонках огнеупорного цеха в одной строке можно указать несколько ID через пробел, запятую, точку с запятой, новую строку или `|`. Ячейка, в которой ID введён как число с разрядными пробелами (`334 864 352`), читается как один ID. Токен бота адресатом не считается: backend отбрасывает значения длиннее 32 символов и отдельно пропускает значение, совпадающее с `MAX_BOT_TOKEN`.

Каждому адресату MAX сообщение уходит отдельным запросом и по очереди, а не одним параллельным пакетом: параллельная отправка теряла последние ID списка. Ответы `429` и `5xx` повторяются до трёх попыток, `4xx` считается окончательным отказом. Отказ конкретного адресата пишется в лог без его идентификатора, а итог отправки — строкой `*.max_sent` с полями `recipientCount` и `deliveredCount`. Если MAX отвечает ошибкой, у пользователя должен быть начатый диалог с ботом, а ID нужного типа из `MAX_RECIPIENT_ID_TYPE` должен быть указан на сайте для персонального адресата или в отдельной групповой колонке ОЦ.

Отчёт по оборудованию рассылается одним кратким сообщением на весь дневной пакет, который backend получает через `/api/dispatcher/equipment-report`. Одиночная отправка одной позиции оборудования через общий endpoint не должна создавать email/MAX-уведомление. Неполный пакет оборудования backend отклоняет.

## Закрытая таблица через service account

Этот режим нужен для production: таблица остаётся `Restricted`, но доступ получает конкретный серверный робот.

1. В Google Cloud должен быть создан service account.
2. В Google Sheets таблице нужно нажать `Share` и выдать этому service account права `Viewer`: текущие интеграции только читают справочники, матрицы и групповых адресатов огнеупорного цеха.
3. JSON-ключ service account должен лежать на Jino вне `public_html`:

```text
~/domains/smb.aonmou.ru/app/secrets/google-service-account.json
```

4. Права на Jino:

```bash
chmod 700 ~/domains/smb.aonmou.ru/app/secrets
chmod 600 ~/domains/smb.aonmou.ru/app/secrets/google-service-account.json
```

5. В `server/.env` включить service account:

```text
GOOGLE_SHEETS_AUTH=service_account
GOOGLE_SERVICE_ACCOUNT_KEY_FILE=/home/users/j/j53403317/domains/smb.aonmou.ru/app/secrets/google-service-account.json
GOOGLE_SHEETS_REFERENCE_URL=https://docs.google.com/spreadsheets/d/1JYz_03AW4j9VXNfdNSBFfdFyxq0Dun_0QnYGvVesGyg/edit?gid=981703922#gid=981703922
GOOGLE_SHEETS_RESPONSIBLE_COLUMN=Ответственный за регистрацию
GOOGLE_SHEETS_INCIDENT_LOCATION_COLUMN=Места (цех/участок)
GOOGLE_SHEETS_REFRACTORY_NOTIFICATION_EMAILS_COLUMN=Адресаты ОЦ (емейлы)
GOOGLE_SHEETS_REFRACTORY_MAX_USER_IDS_COLUMN=Адресаты ОЦ (МАКС)
GOOGLE_SHEETS_REFRACTORY_REVIEW_NOTIFICATION_EMAILS_COLUMN=Адресаты Диспетчеры (емейлы)
GOOGLE_SHEETS_REFRACTORY_REVIEW_MAX_USER_IDS_COLUMN=Адресаты Диспетчеры (МАКС)
GOOGLE_SHEETS_CACHE_TTL_MS=0
```

`GOOGLE_SHEETS_CACHE_TTL_MS=0` отключает backend-кеш Google Sheets: при каждом обновлении страницы frontend заново запрашивает связанные внешние справочники, а backend заново читает таблицу. `/api/production-brands` и `Журнал марок` от этого TTL не зависят.

6. Перезапустить Node-приложение:

```bash
cd ~/domains/smb.aonmou.ru
mkdir -p tmp
touch tmp/restart.txt
```

## Публичная таблица через CSV

Этот режим проще, но таблица должна открываться без входа в Google.

Режим `public_csv` относится только к оставшимся Google Sheets источникам. `Журнал марок` работает через MariaDB/MySQL независимо от выбранного способа чтения Google Sheets.

В `server/.env`:

```text
GOOGLE_SHEETS_AUTH=public_csv
GOOGLE_SHEETS_REFERENCE_URL=https://docs.google.com/spreadsheets/d/1JYz_03AW4j9VXNfdNSBFfdFyxq0Dun_0QnYGvVesGyg/edit?gid=981703922#gid=981703922
GOOGLE_SHEETS_RESPONSIBLE_COLUMN=Ответственный за регистрацию
GOOGLE_SHEETS_INCIDENT_LOCATION_COLUMN=Места (цех/участок)
GOOGLE_SHEETS_REFRACTORY_NOTIFICATION_EMAILS_COLUMN=Адресаты ОЦ (емейлы)
GOOGLE_SHEETS_REFRACTORY_MAX_USER_IDS_COLUMN=Адресаты ОЦ (МАКС)
GOOGLE_SHEETS_REFRACTORY_REVIEW_NOTIFICATION_EMAILS_COLUMN=Адресаты Диспетчеры (емейлы)
GOOGLE_SHEETS_REFRACTORY_REVIEW_MAX_USER_IDS_COLUMN=Адресаты Диспетчеры (МАКС)
GOOGLE_SHEETS_CACHE_TTL_MS=0
```

Если список на сайте не появляется в `public_csv`, сначала проверь доступ: CSV-export ссылка должна открываться в инкогнито без Google login.

## Как поменять таблицу или лист

1. Открой нужную Google Sheets таблицу.
2. Перейди на нужный лист внутри таблицы.
3. Скопируй URL из браузера. В нём важны:
   - id таблицы после `/d/`
   - `gid` нужного листа
4. На сервере открой env backend:

```bash
cd ~/domains/smb.aonmou.ru/app
vi server/.env
```

5. Замени `GOOGLE_SHEETS_REFERENCE_URL`:

```text
GOOGLE_SHEETS_REFERENCE_URL=https://docs.google.com/spreadsheets/d/НОВЫЙ_ID/edit?gid=НОВЫЙ_GID#gid=НОВЫЙ_GID
```

6. Если меняется только лист внутри той же таблицы, меняется только `gid`.
7. Перезапусти Node-приложение:

```bash
cd ~/domains/smb.aonmou.ru
mkdir -p tmp
touch tmp/restart.txt
```

## Как проверить

После перезапуска:

```bash
curl -i https://smb.aonmou.ru/api/dispatcher/forms
curl -i --cookie 'smb_session=...' https://smb.aonmou.ru/api/production-brands
```

В ответе у полей `location` и `responsible` формы `incident` должен быть `select`:

```json
{
  "name": "location",
  "type": "select",
  "options": ["..."]
}
```

```json
{
  "name": "responsible",
  "type": "select",
  "options": ["..."]
}
```

Если `type` остался `text`, backend не смог прочитать Google Sheets или не нашёл нужную колонку.

## Включение email-рассылки

Сохранение Email пользователя на сайте или чтение групповых адресатов ОЦ из Google Sheets не отправляет письма само по себе. Для реальной отправки нужно добавить SMTP-настройки в `server/.env`:

```text
EMAIL_NOTIFICATIONS_ENABLED=true
EMAIL_FROM=адрес_отправителя
EMAIL_SUBJECT_PREFIX=НМОУ Вектор
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=логин_smtp
SMTP_PASS=пароль_smtp
```

Если SMTP-сервер работает на порту `465`, обычно нужно поставить `SMTP_SECURE=true`. Если почтовый сервер разрешает отправку без логина и пароля, `SMTP_USER` и `SMTP_PASS` можно оставить пустыми.

Рассылка выполняется только после успешного сохранения формы, pending-ревизии либо подтверждения таблицы ОЦ в БД. Если SMTP временно недоступен, данные остаются сохранёнными, а ошибка записывается в лог backend как `dispatcher_notifications.email_send_failed`, `refractory_review_notifications.email_send_failed` или `refractory_notifications.email_send_failed`.

## Включение MAX-рассылки

Сохранение MAX ID пользователя на сайте не отправляет сообщения само по себе. Для отправки через бота нужно добавить в `server/.env`:

```text
MAX_NOTIFICATIONS_ENABLED=true
MAX_BOT_TOKEN=токен_бота_MAX
MAX_API_BASE_URL=https://platform-api2.max.ru
MAX_RECIPIENT_ID_TYPE=user_id
MAX_SUBJECT_PREFIX=НМОУ Вектор
MAX_CA_CERT_FILE=
```

Токен бота не коммитить в git и не класть в frontend env. Он нужен только backend-у.

`MAX_RECIPIENT_ID_TYPE=user_id` означает, что сохранённые идентификаторы пользователей будут отправлены в MAX как `user_id`. Если используются ID чатов, поставь:

```text
MAX_RECIPIENT_ID_TYPE=chat_id
```

Если `chat_id` в MAX показан с минусом, например `-123456789`, на сайте или в групповой колонке ОЦ нужно оставить его с минусом. Backend читает такое значение как единый ID.

Если на Jino при тесте MAX появляется ошибка `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`, значит Node.js не доверяет цепочке сертификатов `platform-api2.max.ru`. Для MAX не нужно отключать TLS глобально. Нужно положить сертификат Минцифры в закрытую папку проекта и указать путь:

```bash
cd ~/domains/smb.aonmou.ru/app
mkdir -p secrets
curl -L https://gu-st.ru/content/Other/doc/russiantrustedca.pem \
  -o secrets/russiantrustedca.pem
chmod 700 secrets
chmod 600 secrets/russiantrustedca.pem
```

После этого добавь в `server/.env`:

```text
MAX_CA_CERT_FILE=/home/users/j/j53403317/domains/smb.aonmou.ru/app/secrets/russiantrustedca.pem
```

Файл должен лежать вне `public_html` и не должен попадать в git. Не используй `NODE_TLS_REJECT_UNAUTHORIZED=0`: это отключает проверку сертификатов для всего Node-процесса.

Персональные MAX ID для инцидентов, посетителей, оборудования и выработки берутся из `app_users` по server-owned матрице настроек. Администратор вводит их на сайте во вкладке `Учётные записи → Уведомления`.

Для подтверждённых таблиц ОЦ MAX ID отдельно читаются из строк `2–20` колонки `Адресаты ОЦ (МАКС)`; в одной ячейке также разрешено несколько ID.

Для новых pending-таблиц ОЦ MAX ID диспетчеров отдельно читаются из строк `2–20` колонки `Адресаты Диспетчеры (МАКС)`; в одной ячейке также разрешено несколько ID.

Рассылка выполняется только после успешного сохранения формы, pending-ревизии либо подтверждения таблицы ОЦ в БД. Если MAX временно недоступен или токен неверный, данные остаются сохранёнными, а ошибка записывается в лог backend как `dispatcher_notifications.max_send_failed`, `refractory_review_notifications.max_send_failed` или `refractory_notifications.max_send_failed`. Если для события нет ни одного включённого персонального MAX ID или в групповой колонке ОЦ нет адресатов, backend пишет соответствующее событие `*.max_no_recipients`.

## Что происходит со старыми данными

Справочник влияет только на новые варианты выбора в форме. Уже отправленные регистрации хранят выбранное текстовое значение в payload отправки, поэтому удаление человека или места из Google Sheets не удаляет это значение из старой аналитики и истории.

Для будущих столбцов нужно использовать тот же подход: новые формы получают актуальные варианты из Google Sheets, а отправленные записи продолжают хранить выбранное значение отдельно от текущего справочника.
